# 要件書

> このリポジトリのサイトは、架空の会社の採用サイトです。実在の会社・施設・人物とは関係ありません。

同じ採用サイトを Vanilla（ビルドなし）、Astro、Next.js の3つの構成で作り、要件が増えたときに各構成のどこが変わるかを比べる。この要件書は3構成に共通の条件で、どの構成もここに書いた受け入れ条件を満たすように作る。

## 会社の設定

| 項目 | 内容 |
|---|---|
| 社名 | 株式会社ロウリュ研究所（架空） |
| 事業 | 都市型のサウナ施設を5店舗運営し、テントサウナの貸し出しもしている |
| 店舗 | 店舗は「研究棟」と呼ぶ。神田研究棟、中野研究棟、横浜研究棟、大宮研究棟、湖畔研究棟（テントサウナの拠点） |
| 雰囲気 | 仕事にはまじめ。文言だけ少し遊ぶ。見た目はふつうの採用サイトとして通用するものにする |

## 求人データ

求人は CMS で管理する。このリポジトリでは本物の CMS を使わず、microCMS と同じ形で返す疑似 CMS（`spec/` に置く）を使う。

| フィールド | 型 | 内容 |
|---|---|---|
| `id` | 自動 | 求人の ID |
| `title` | テキスト | 求人のタイトル（例：「神田研究棟の熱波師（正社員）」） |
| `category` | セレクト（1つ） | `store` / `facility` / `office` のいずれか |
| `location` | セレクト（1つ） | 研究棟の名前、または「本社」 |
| `employmentType` | セレクト（1つ） | 正社員 / アルバイト |
| `salary` | テキスト | 給与 |
| `body` | リッチエディタ（HTML） | 仕事内容 |
| `requirements` | テキストエリア | 応募の条件 |
| `publishedAt` / `revisedAt` | 自動 | 公開日時と更新日時 |

- 一覧の API は `contents` / `totalCount` / `offset` / `limit` を返す
- 求人の件数は 0 / 10 / 100 / 500 件の4段階に切り替えられるようにする。本文の長さはそろえる
- API キーのないリクエストは拒否する。キーはダミーの値にし、本物の値はリポジトリに置かない

## 受け入れ条件

### すべてのフェーズに共通

- 見た目は `spec/design/` の見本の HTML に合わせ、共通 CSS（1ファイル）をそのまま使う。HTML のクラス名と構造は `spec/design/README.md` の約束に従う
- スマホと PC でレイアウトが崩れない
- JS を切っても本文とナビゲーションが読める。JS が要るのは、スマホのメニューの開閉だけ
- `<title>` と `<meta name="description">` がページごとに違う
- 存在しないパスでは、404 のページが 404 のステータスで返る
- 全ページで、ヘッダーとフッターの内容が同じ

### Phase 1：静的な採用サイト

- ヒーロー画像は AVIF と WebP を出し分け、幅 640 / 1280 / 1920 の srcset を持つ
- ヒーロー画像に `fetchpriority="high"` が付き、遅延読み込みされない
- すべての画像に `width` と `height` があり、CLS が 0.1 未満
- 応募ボタン（文言は「応募する」、リンク先は `/process/`）がヘッダーと各ページにある

### Phase 2：求人（CMS 連携）

- 求人ページはビルド時に疑似 CMS のデータから作る
- 求人詳細の本文、`<title>`、OGP が最初の HTML に入っている（ブラウザで CMS からデータを取って表示する作りにはしない）
- 求人が0件でも一覧ページが壊れず、「現在募集している職種はありません」と出る
- 存在しない ID の求人詳細は 404 になる
- 求人数 0 / 10 / 100 / 500 件のどれでもビルドが成功する

### 仕様変更：求人の URL とヘッダー

- 求人詳細の URL を `/jobs/{id}/` から `/jobs/{category}/{id}/` に変え、職種カテゴリ別の一覧を足す
- 旧 URL（`/jobs/{id}/`）を開くと、新 URL にたどり着く。旧 URL と新 URL の対応は、ビルド時に CMS のデータから作る（301 は求めない）
- ヘッダーのメニューに「職種から探す」を足す
- 応募ボタンの文言を「まずはサウナ見学から」に、リンク先を `/process/#visit` に変える。全ページで変わっている

### Phase 3：求人原稿のプレビュー

プレビューは、サーバーで組み立てる版（サーバー版）と、ブラウザで組み立てる版（CSR 版）の2つを作る。

両方に共通する条件

- CMS の編集画面で「プレビュー」を押すと、公開前の求人原稿が、公開済みの求人詳細と同じレイアウトで表示される
- `draftKey` がない、または違う場合は求人を表示しない
- プレビュー以外のページは静的に配信され、HTML が仕様変更のあとから変わっていない
- プレビューのページに `noindex` が付いている

サーバー版だけの条件

- API キーがブラウザに出ない

CSR 版だけの条件

- プレビューのページ自体は静的な HTML にする
- ブラウザに置く API キーは GET 権限だけのもので、サーバー版のキーとは別にする。このキーで書き込みや下書きの一覧取得をすると拒否される

## 構成ごとの約束

| 構成 | 約束 |
|---|---|
| Vanilla | フレームワークを使わない。Phase 2 からは、ビルド用の Node スクリプトを持ってよい |
| Astro | `.astro` だけで作り、React などの UI フレームワークは入れない。既定の静的出力で作る |
| Next.js | App Router で作り、`output: 'export'` で静的に書き出す。Phase 3 のサーバー版だけは export をやめてよい |

- 書き方は、各技術の公式ドキュメントに沿った「その技術らしい書き方」にする
- 計測と E2E は、3構成とも同じローカルの静的サーバーで行う

## やらないこと

- ホスティングへのデプロイと、デモサイトの公開
- 応募フォーム（応募ボタンは選考の流れのページに飛ぶだけ）
- SSR やエッジでの配信（Phase 3 のサーバー版のプレビューを除く）
