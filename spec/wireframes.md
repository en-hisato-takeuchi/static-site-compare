# 画面設計

`spec/requirements.md` のページを、どの要素をどの順で並べるかまで決める。見た目（色、余白、フォント）は `spec/design/` で決めるので、ここでは扱わない。文言の中身は `spec/assets/` で用意し、ここに書いた文言は仮のもの。

## サイトマップ

```
/                         トップ
├── /about/               私たちについて
├── /workplace/           働く環境
├── /process/             選考の流れ（#visit：サウナ見学の案内）
├── /jobs/                求人一覧（Phase 2）
│   ├── /jobs/page/{n}/   求人一覧の2ページ目以降（Phase 2）
│   ├── /jobs/{id}/       求人詳細（Phase 2。仕様変更で旧 URL になる）
│   ├── /jobs/{category}/              職種カテゴリ別の一覧（仕様変更）
│   │   ├── /jobs/{category}/page/{n}/ その2ページ目以降（仕様変更）
│   │   └── /jobs/{category}/{id}/     求人詳細（仕様変更）
│   └── /jobs/preview/    求人原稿のプレビュー（Phase 3）
└── 404
```

## ひな形

ページは5つのひな形で作る。同じひな形のページは、HTML の構造が同じになる。

| ひな形 | 使うページ |
|---|---|
| トップ | `/` |
| 文章ページ | `/about/` `/workplace/` `/process/` |
| 求人一覧 | `/jobs/` `/jobs/page/{n}/` `/jobs/{category}/` `/jobs/{category}/page/{n}/` |
| 求人詳細 | `/jobs/{id}/` `/jobs/{category}/{id}/` `/jobs/preview/` |
| 404 | 存在しないパス |

ヘッダーとフッターは全ひな形で共通。

## 共通ヘッダー

PC では1行に並べる。スマホでは、ロゴとメニューボタンだけを出し、メニューボタンで残りを開閉する。

1. ロゴ（社名「株式会社ロウリュ研究所」。トップへのリンク）
2. グローバルメニュー
   - 私たちについて（`/about/`）
   - 働く環境（`/workplace/`）
   - 選考の流れ（`/process/`）
   - 求人一覧（`/jobs/`。Phase 2 から）
   - 職種から探す（`/jobs/#category-nav`。求人一覧の職種カテゴリの切り替えへ飛ぶ。仕様変更から）
3. 応募ボタン（Phase 1 は「応募する」→ `/process/`。仕様変更で「まずはサウナ見学から」→ `/process/#visit`）
4. メニューボタン（スマホだけ。JS で開閉する。JS を切ったときはメニューを開いた状態で出す）

## 共通フッター

1. 社名と一言（「今日も、どこかの研究棟で誰かがととのっている。」）
2. サイト内リンク（グローバルメニューと同じ並び）
3. 注記「このサイトは架空の会社の採用サイトです」
4. 画像のクレジットへのリンク（GitHub 上の `spec/README.md`）
5. コピーライト

## トップ

1. ヒーロー
   - ヒーロー画像（ページの横幅いっぱい。LCP の対象）
   - キャッチコピー（例：「熱いのは、サウナだけじゃない。」）
   - サブコピー（1〜2行）
   - 応募ボタン
2. 私たちについて（要約）
   - 見出し、本文2〜3行、`/about/` へのリンク
3. 数字で見るロウリュ研究所
   - 数字を3つ並べる（例：研究棟5棟、1日の熱波の回数、水風呂の水温16℃）
4. 新着求人（Phase 2 から）
   - 求人カードを3枚。並びは求人一覧のカードと同じ
   - 「求人一覧を見る」リンク
   - 求人が0件のときは「現在募集している職種はありません」
5. 応募の案内
   - 一言と応募ボタン

## 文章ページ

`/about/`、`/workplace/`、`/process/` で共通の構造。

1. ページの見出し（h1）と導入文
2. 画像1枚（任意。幅いっぱいではなく本文の幅）
3. 節を並べる（節ごとに h2 と本文。必要なら箇条書きか表）
4. 応募の案内（一言と応募ボタン）

各ページの節

| ページ | 節 |
|---|---|
| 私たちについて | 会社の紹介／研究棟の一覧（5棟の名前と一言）／大事にしていること |
| 働く環境 | 福利厚生（例：サウナ入り放題。ただし業務時間外に限る）／社員の声（3人。名前、職種、一言）／一日の流れ |
| 選考の流れ | 選考のステップ（応募 → 書類選考 → 面接 → 最終面接 → 内定）／サウナ見学の案内（`id="visit"`。仕様変更のリンク先）／よくある質問 |

選考のステップは番号付きのリストにする。最終面接の説明に「最終面接はサウナで行います（任意）」と入れる。

## 求人一覧

1. ページの見出し（h1）
   - `/jobs/` は「求人一覧」
   - `/jobs/{category}/` は「店舗スタッフの求人」のようにカテゴリ名を入れる
2. 職種カテゴリの切り替え（仕様変更から。`id="category-nav"`）
   - 「すべて」と3カテゴリのリンクを並べる。今いるカテゴリに `aria-current="page"` を付ける
3. 件数（例：「全128件」）
4. 求人カードのリスト（10件ずつ）。カード1枚の中身
   - タイトル（求人詳細へのリンク）
   - カテゴリ、勤務地、雇用形態
   - 給与
   - 公開日
5. ページ送り
   - 前へ／ページ番号／次へ。今いるページに `aria-current="page"` を付ける
   - 1ページで収まるときは出さない
6. 求人が0件のとき
   - 3と4と5の代わりに「現在募集している職種はありません」

## 求人詳細

1. パンくず（トップ → 求人一覧 → 求人タイトル。仕様変更からは、求人一覧のあとにカテゴリを挟む）
2. 求人タイトル（h1）
3. 概要（カテゴリ、勤務地、雇用形態、給与、公開日）。定義リスト（`<dl>`）で並べる
4. 仕事内容（CMS のリッチエディタの HTML をそのまま入れる）
5. 応募の条件
6. 応募ボタン
7. 一覧に戻るリンク

プレビュー（Phase 3）も同じ構造にし、先頭に「プレビュー中：この求人はまだ公開されていません」という帯を足し、`<meta name="robots" content="noindex">` を入れる。`draftKey` がない、または違うときは、2〜7の代わりに「プレビューできる求人が見つかりません」と出す。

## 404

1. 見出し（例：「このページは、ととのいすぎて消えてしまいました」）
2. 一言（ページが見つからない旨）
3. トップへのリンクと、求人一覧へのリンク（Phase 2 から）

## ページごとの `<title>` と `<meta name="description">`

`<title>` は「ページ名 | 株式会社ロウリュ研究所 採用サイト」の形にする（トップだけは「株式会社ロウリュ研究所 採用サイト」）。求人詳細は求人タイトルを、カテゴリ別の一覧はカテゴリ名を、ページ送りの2ページ目以降は「（2ページ目）」を入れて、ページごとに違う値にする。

`<meta name="description">` は、静的ページは `spec/assets/` の文言に、求人詳細は仕事内容の先頭120文字にする。

求人詳細には OGP（`og:title`、`og:description`、`og:url`、`og:type`）を入れる。値は `<title>` と `<meta name="description">` に合わせる。どちらも最初の HTML に入っていること（要件書の Phase 2 の受け入れ条件）。
